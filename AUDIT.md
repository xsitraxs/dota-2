## Подробные находки

### C1 · 🟠 Урон универсальных героев считается неверно

`assets/analysis.js:12-21` (`heroDamage`):

```js
const attr = h.primary_attr === 'all'
  ? Math.max(h.stats.base_str || 0, h.stats.base_agi || 0, h.stats.base_int || 0)  // ← не так
  : h.stats[ATTR_KEY[h.primary_attr]] || 0;
```

По механике Dota (7.33+) каждый пункт **любого** атрибута даёт универсальному герою **+0.7**
к урону, то есть бонус = `0.7 × (str + agi + int)`, а не `max(str, agi, int)`.
Затронуты **22 героя** из 127 (`primary_attr: 'all'`).

| Герой | Урон по формуле приложения | По формуле 0.7×сумма | Занижение |
| --- | --- | --- | --- |
| Bane | 50.0 | 75.3 | −25.3 |
| Void Spirit | — | — | −22.9 |
| Arc Warden | — | — | −22.2 |
| Windranger | 50.0 | 69.2 | −19.2 |
| Enigma | 43.0 | 59.8 | −16.8 |

**Влияние:** карточка героя («Урон автоатаки»), фактор «Урон автоатаки на 1 уровне» в разборе
лейна, а значит и итоговый score лейна/пиков в матчах с универсалами — смещены против них.
Среднее занижение ≈ 19 пунктов урона.

**Исправление:**

```js
const attr = h.primary_attr === 'all'
  ? 0.7 * ((h.stats.base_str || 0) + (h.stats.base_agi || 0) + (h.stats.base_int || 0))
  : h.stats[ATTR_KEY[h.primary_attr]] || 0;
```

После правки перепрогнать `npm test` — пороговые кейсы (Sniper/Viper, QoP/Huskar) могут
сдвинуться; заодно стоит добавить тест-кейс с универсалом (например, Bane против кого-то).
*Оговорка:* если в 7.41 механика универсалов отличалась — сверьте формулу с клиентом, но
текущий `max()` не соответствует ни одной известной версии механики.

`assets/app.js:444`:

```js
${list.slice(0, 220).map(([k, it]) => `...
```

В датасете 409 предметов без рецептов, но без поиска рисуются первые 220 (сортировка по цене —

### C3 · 🟠 Битый `localStorage` ломает приложение без пути восстановления

`loadDraft()` (`assets/app.js:694`) не валидирует сохранённые слоги героев. При неизвестном
слоге рендер драфта падает:

- `assets/app.js:188` — `DATA.heroes[s].localized_name` в селекте «Их мид» (без проверки);
- `assets/app.js:712-713` — то же в `planAsText()` (кнопка «Скопировать план текстом»).

Исключение из `render()` ловится `catch` у `boot()` и показывается как «Ошибка загрузки
данных» — **на каждом старте**, пока пользователь сам не очистит `localStorage`
(воспроизведено в jsdom: `dp.draft` со слогом `no_such_hero` → вкладка драфта недоступна).

**Исправление:** в `loadDraft` отфильтровать слоги через `DATA.heroes` и привести массивы к
корректной длине; в `planAsText`/селекте добавить защиту (`DATA.heroes[s]?.localized_name || s`).
Как крайняя мера — `catch` в `loadDraft` может сбрасывать `dp.draft` при ошибке рендера.

### D1 · 🟠 `ember_spirit` без тегов механик

В `data/kb/tags.json` размечено 126 героев из 127 — пропущен Ember Spirit. Для него не
сработают теговые угрозы/контрмеры и комбо-правила (для сравнения, у остальных теги есть даже
у новичков `kez`/`largo`). Для героя с невидимостью через Fire Remnant и сильным роумом логично
хотя бы `gap_close`, `burst_magical`, `roam_ganker`, `waveclear`.

### D2 · 🟠 Нет иконок у трёх героев

`ringmaster`, `kez`, `largo` отображаются буквенным аватаром. Сборщик это логирует
(`build_data.mjs: иконок скопировано: 124/127`), но иконки существуют в источнике
`M-Hasan-Ibrahim/Dota2HeroInfoAndIcons` — вероятно, не совпало имя файла (`localized_name`).
Стоит проверить сопоставление в `build_data.mjs` (там матч по `localized_name`) и, например,
добавить fallback-таблицу имён.

### T1 · 🟠 Тесты жёстко завязаны на текущий размер датасета

- `tools/test_engine.mjs:38` — `Object.keys(heroes).length === 127` — упадёт при добавлении
  героя в датасет, хотя данные валидны;
- `tools/test_ui.mjs` — `$$('#pickerGrid .pick').length === 36`, `=== 127`, `> 400`;
- `tools/test_engine.mjs:40` — `Object.keys(plans).length >= 36` считает служебный `_comment`
  (см. D3).

**Исправление:** использовать `>=` для количественных гейтов, а точные числа хранить в
`data/meta.json` и сравнивать с ними (`heroes.length === meta.heroes`).

### T2 · 🟠 UI-тесты не в CI

`.github/workflows/pages.yml` гоняет только `test_engine.mjs`. `test:ui` требует сервер и
`npm install`, поэтому регрессии интерфейса (например, C2) не ловятся автоматически. В job
можно поднять `python3 -m http.server` фоном и выполнить `npm ci && npm run test:ui`.

### C4 · 🟡 Галочки чеклиста «переезжают»

`assets/app.js:307` — `data-check="${i}"` хранит состояние по индексу пункта
(`state.checks`). Чеклист собирается из угроз (`buildChecklist`) и меняет длину/порядок при
смене драфта — старые галочки применяются к другим пунктам.
**Исправление:** ключевать по хэшу текста пункта, а не по индексу.

### C5 · 🟡 Таймер: запись в `localStorage` каждую секунду и полный ре-рендер

`startTimerLoop()` (`assets/app.js:675`) раз в секунду вызывает `render()`, который
пересобирает весь `#view` через `innerHTML` и вызывает `saveDraft()` (`assets/app.js:612`).
Итог: запись в `localStorage` каждую секунду, сброс прокрутки/фокуса на вкладке «Тайминги».
**Исправление:** обновлять только текст часов и блок «Ближайшие события», `saveDraft()` вызывать
по изменениям драфта, а не в `render()`.

### C6 · 🟡 Дубликаты героев в слотах

Пикер (`openPicker`) не проверяет, не выбран ли герой уже в другом слоте: один и тот же враг
может стоять дважды (угрозы тогда задублируют героя в списке), «свой герой» может совпадать
с врагом. Стоит выключать уже занятых героев в пикере.

### C7 · 🟡 `counterPicks` предлагает занятых героев

`assets/analysis.js` (`counterPicks`) не исключает `state.me` и союзников — в списке
«Кого ещё можно взять» может оказаться уже выбранный герой. Легкий фильтр в `renderDraft`
перед вызовом решает вопрос.

### C8 · 🟡 Тайминги продублированы строками

`planAsText()` (`assets/app.js: ~740`) и `buildChecklist()` (`assets/analysis.js`) пишут
тайминги руками («вода 2:00/4:00 · руна силы 6:00…») вместо чтения `data/kb/timings.json`.
Сейчас строки совпадают с данными, но при обновлении `timings.json` разойдутся. Вынести
тексты в `timings.json` (или собирать из событий).

### S1 · 🟡 `extractTarGz`: tar-slip и PAX-заголовки

`tools/build_data.mjs:50-72`: имя файла из архива подставляется в `path.join(destDir, rel)`
без проверки на `..` и абсолютные пути — запись может выйти за пределы `destDir`. Также
записи типа `x` (PAX extended header) записываются как обычные файлы вместо разбора,
GNU long name (`L`) не поддерживается. Источник — `codeload.github.com` по HTTPS, так что
эксплуатация маловероятна; исправление дешёвое:

```js
const out = path.resolve(destDir, rel);
if (!out.startsWith(path.resolve(destDir) + path.sep)) continue; // защита от tar-slip
```

и пропуск типов, отличных от файловых (`0`, `\0`), без записи мусора.

### S2 · 🟡 Actions не закреплены по SHA

`actions/checkout@v4`, `setup-node@v4`, `configure-pages@v5`, `upload-pages-artifact@v3`,
`deploy-pages@v4` — теги двигаются. Для workflows с `pages: write`/`id-token: write` принято
закреплять версии по commit SHA (или хотя бы осознанно следить за обновлениями).

### L1 · 🟡 Нет LICENSE / NOTICE

Производные данные — из `odota/dotaconstants` (MIT), иконки — из
`M-Hasan-Ibrahim/Dota2HeroInfoAndIcons`. В репозитории нет файла лицензии и NOTICE с
атрибуцией. README упоминает источники, но для публичного репозитория стоит добавить
`LICENSE` (например, MIT) и `NOTICE` со списком сторонних компонентов.

### C9 · ⚪ Мёртвый код

- `assets/app.js` (`renderHeroCard`): `${ult ? '' : ''}` — выражение всегда даёт пустую строку;
- `tools/build_data.mjs`: `itemKeys` (по `dname`) вычисляется, но не используется;
  массив `warn` никогда не заполняется;
- `buildChecklist({ threats, combos, data })` — параметр `data` не используется.

### C10 · ⚪ Неточная атрибуция «по тексту способностей»

В `threatsFor()` (`assets/analysis.js`) `autoEvidence` ведётся общим словарём на всех героев,
а флаг `auto` берётся от первого героя, создавшего угрозу. На практике список `evidence`
может показать способность героя, у которого тег был ручным, и наоборот. На решение не влияет,
но сбивает с толку при чтении. Привязать evidence к паре (тег, герой).

### D3 · ⚪ «37 планов» на самом деле 36

В `plans_mid_a.json` + `plans_mid_b.json` 36 героев + служебный ключ `_comment`.
README («мидовые планы (37 героев)») и вывод `test_engine` («мидовых планов в базе — 37»)
считают и его; UI-тест честно ждёт 36. Поправить README и исключить `_comment` из подсчёта.
