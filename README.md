# Драфт-помощник Dota 2 (патч 7.41)

Локальный инструмент для мидового игрока: показывает, **что делать в этом матче** — как играть лейн против их мида,
какие угрозы несёт их драфт и чем на них отвечать, что покупать (с ценами 7.41) и когда.

Работает офлайн, без сторонних API, винрейтов и телеметрии: только игровые данные вашего патча + правила, выведенные из механик.

## Онлайн

**<https://xsitraxs.github.io/dota-2/>** — открывается прямо в браузере, ничего ставить не нужно.

Сайт обновляется при каждом пуше в `main`, а workflow
[`.github/workflows/pages.yml`](.github/workflows/pages.yml) подстраивается под настройку
**Settings → Pages → Source**:

| Source | Что происходит |
| --- | --- |
| **Deploy from a branch** | GitHub сам собирает сайт из корня `main`; workflow в этом режиме прогоняет `node tools/test_engine.mjs` на тех данных, что уедут в прод, и не мешает |
| **GitHub Actions** | workflow дополнительно собирает чистый артефакт — только `index.html` + `assets/` + `data/`, без `tools/` и README — и публикует его через `actions/deploy-pages` |

В обоих режимах перед публикацией проверяются движок и интерфейс (jsdom), так что сломанные данные 7.41 или регрессия вёрстки в прод не уедут.
Кнопка **Re-run jobs** на странице Actions или ручной запуск workflow (`workflow_dispatch`)
перепубликуют сайт без нового коммита.

## Запуск локально

```bash
# из корня репозитория
python3 -m http.server 8000
# открыть http://localhost:8000
```

Или любой статический сервер: `npx serve .`, `php -S localhost:8000` и т.п. Приложение чисто статическое —
`index.html` + `assets/` + `data/`, все ссылки относительные, поэтому одинаково работает и в корне домена,
и по адресу вида `xsitraxs.github.io/dota-2/`.

## Что внутри

| Раздел | Что делает |
| --- | --- |
| **Драфт** | Выбираешь своего мида, до 5 врагов (и отмечаешь их мида) — получаешь вердикт по лейну с разбором факторов, список угроз их драфта с конкретными ответами, свой план закупа и скиллов, рекомендации по пикам и чеклист на игру |
| **Скриншот** | Вставляешь скриншот экрана пика (Ctrl+V, перетаскивание или файл) — приложение находит сетку карточек, распознаёт героев по локальным иконкам и заполняет драфт. Ошибки видно сразу (кнопки-альтернативы и список), сетку можно пересобрать вручную: указать колонки и строки |
| **Герои** | Все 127 героев 7.41: цифры клиента, способности с маной/КД/описанием, врождённые способности, изменения в 7.41, мидовые планы (36 героев), сильные и слабые матчапы |
| **Предметы** | Полный список предметов 7.41 с ценами, активными/пассивными эффектами, составом и патч-нотами. Первая порция карточек рисуется сразу, остальные подгружаются по мере прокрутки (или кнопкой «Показать ещё»), а поиск всегда идёт по всем предметам |
| **Патч 7.41** | Патчноуты (7.41f → 7.40): общие изменения, предметы, герои — с переходами в карточки |
| **Тайминги** | Живой таймер матча: руны, святилище мудрости, Рошан, Торментор, день/ночь — с обратным отсчётом |
| **Как это работает** | Источники данных, логика движка и честные ограничения |

Кнопка «Скопировать план текстом» собирает всё решение в один текст — удобно кинуть себе в сохранённые или в чат команде.

## Откуда данные

- **Игровые константы** — [odota/dotaconstants](https://github.com/odota/dotaconstants) (MIT): герои, способности с цифрами,
  предметы, патчноуты. Обновляются из клиента игры.
- **Иконки героев** — [M-Hasan-Ibrahim/Dota2HeroInfoAndIcons](https://github.com/M-Hasan-Ibrahim/Dota2HeroInfoAndIcons).
- Собранный снимок лежит в `data/` и закоммичен, чтобы приложение работало без сети.

## Обновление данных при выходе нового патча

```bash
node tools/build_data.mjs          # скачает свежие константы и иконки, пересоберёт data/, проверит файлы знаний
node tools/build_data.mjs --offline /path/to/dotaconstants   # из локальной копии
node tools/test_engine.mjs         # прогон проверок движка на собранных данных
```

Сборщик не просто копирует JSON: он **валидирует файлы знаний** (`data/kb/*.json`) — каждая ссылка на героя,
способность и предмет должна существовать в текущем патче. Это ловит устаревшие названия (например, удалённые
или переименованные предметы) сразу на сборке.

## Проверки

```bash
npm install            # один раз: jsdom (проверка интерфейса) и eslint (линтер)
npm run lint           # eslint: recommended + no-unused-vars, eqeqeq, no-var, prefer-const
npm test               # движок разбора драфта на собранных данных (без браузера, быстрый)
npm run test:recognize # распознавание на синтетических скриншотах (нужен ImageMagick)
python3 -m http.server 8000 &   # для следующей проверки нужен запущенный сайт
npm run test:ui        # прогон интерфейса в jsdom: выбор драфта, вердикт, закуп, все вкладки, таймер, скриншот
```

`npm test` проверяет логику: матчапы (QoP против Huskar — тяжёлый лейн), сборку угроз и контрмер, комбо-правила,
рекомендации по пикам, план закупа и чеклист, все ссылки в базе знаний. `npm run test:ui` открывает страницу
в jsdom с полифиллом `fetch`, кликами собирает драфт и проверяет, что интерфейс рисует вердикт, угрозы, закуп
и сохраняет состояние в `localStorage` (включая подгрузку списка предметов и чистку устаревших галочек).
`npm run test:recognize` склеивает из настоящих иконок синтетические «скриншоты» (ImageMagick) и проверяет,
что движок находит сетку и героев на испорченных кадрах: пониженная яркость, повышенный контраст, размытие,
JPEG, масштаб 55 %, шум, две строки карточек, полоса внутри большого кадра и ручная нарезка. Все проверки
прогоняются в CI (на push в `main` и на pull request) перед публикацией сайта.

## Важно про патч 7.41

В 7.41 **фацеты удалены из игры**, а врождённые способности больше не зависят от уровней других способностей
(скейлятся от уровня героя). Поэтому в интерфейсе нет выбора фацетов: планы и советы построены на актуальных
наборах способностей 7.41.

## Распознавание скриншота

Вкладка «Скриншот» работает целиком в браузере и офлайн: кадр уменьшается, каждая ячейка превращается
в компактную «подпись» (разностный хеш 17×16 + средние цвета 4×4) и сравнивается с подписями локальных
иконок из `data/templates.json`. Никаких внешних сервисов, картинка не покидает браузер.

```bash
node tools/build_templates.mjs   # пересобрать подписи (после обновления иконок; нужен ImageMagick)
```

Порядок работы: автопоиск сетки по профилям яркости и градиента (границы области содержимого, шаг решётки,
полосы рядов, подгонка фазы сетки по узнаваемости карточек) → сравнение ячеек с иконками → до 5 кандидатов
на ячейку. Если автопоиск ошибся, колонки, строки и область задаются вручную, а любой распознанный герой
правится списком или кнопкой-альтернативой. Кнопки «В противники» / «В союзники» заполняют пустые слоты
драфта по порядку ячеек.

Что проверено: на синтетических кадрах (настоящие иконки, склеенные в карточки) автопоиск и распознавание
проходят все 26 проверок, включая пониженную яркость, контраст, размытие, JPEG, масштаб 55 %, шум, две
строки карточек и полосу внутри большого кадра. На **реальных** скриншотах экрана пика авто-режим пока
ошибается: в игре карточки обрезаны иначе, чем иконки в `data/icons/`, баны обесцвечены, а ряды разделены
подписями — для таких кадров надёжнее задать область и сетку вручную (удобно нарезать по одному ряду
команды и заполнять драфт по частям). Чтобы авто-режим заработал и на настоящих кадрах, нужны образцы
карточек из игры — из них соберём дополнительные кадры шаблонов.

## Ограничения

- Это не статистика винрейтов: цифры берутся из клиента, а суждения о матчапах — из базы знаний репозитория,
  их стоит проверять на практике.
- Герой, добавленный после сборки данных, отобразится только тем, что есть в датасете.
- Винрейты и данные матчей намеренно не используются: инструмент должен работать офлайн и не зависеть от сторонних сервисов.
- Автопоиск сетки рассчитан на карточки героев на однородном фоне (экран пика, полоса пиков). На необычной
  вёрстке сетку стоит задать вручную: колонки/строки в панели «Сетка карточек». Герои без иконок в `data/`
  (сейчас `ringmaster`, `kez`, `largo`) распознаванию недоступны — их подставляет пользователь.
