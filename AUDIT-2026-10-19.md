## 1. Безопасность

### Проверено
- `npm audit --json` — **0 vulnerabilities** (prod 1, dev 115). `npm ls` после `npm ci` без ошибок.
- **XSS:** весь `innerHTML` в `assets/app.js` проходит через `esc()` (10 точек: `view.innerHTML`, `modal.innerHTML`, карточки героев/предметов/способностей). Ручная проверка 8 вставок — все экранированы. `esc` покрывает `& < > " '`.
- **Prototype pollution:** `isHero`, `shot.picks`, `DATA.icons` — везде `Object.prototype.hasOwnProperty.call`. Тест `test_ui` специально ломает `localStorage` значениями `constructor/__proto__/toString/hasOwnProperty` и массива-повторов — интерфейс не падает.
- **Tar-slip:** `tools/datalib.mjs:extractTar` — режет абсолютные пути, `../`, срезает `repo-ref/` префикс, игнорирует symlink/device, PAX/GNU `longname`. Покрыто тестом `test_data` (распаковка tar.gz в tmpdir, проверка записи вне dest).
- **Секреты:** `grep token/secret/password` — только упоминания `github.token` в workflow и `GH_TOKEN` в шаге `Detect Pages source` (корректно, `persist-credentials: false`).
- **localStorage:** парсинг в `try/catch`, инвалид JSON/массив/`null`/строка → стартовый экран, чистка `constructor`/дублей, удаление `false`-ключей (а не сохранение).

### CI-защита (`.github/workflows/pages.yml` — 9698 байт)
- `permissions: {}` на уровне workflow, `build: {contents:read, pages:read}`, `deploy: {pages:write, id-token:write}` — least privilege, проверяется `test_ci` (6 групп, 30+ assert).
- `actions/checkout@3d3c42e... # v7.0.1`, `setup-node@949feb... # v7.1.0`, `configure-pages@45bfe0... # v6`, `upload-pages-artifact@fc324d... # v5`, `deploy-pages@368f82... # v5.0.1` — все закреплены полным SHA.
- `concurrency: pages-ci-${{pr.number||ref}}` + `cancel-in-progress: pr_only` — PR не вытесняет публикацию `main`; `pages-deploy` — `cancel-in-progress:false`, сериализован.
- `npm ci --ignore-scripts` — нет выполнения install-скриптов зависимостей.
- `deploy` не исполняет код репозитория — единственный шаг `actions/deploy-pages`.
- Скрипт `Detect Pages source` различает `workflow/legacy/none/unknown`, на `push/main` без доступа к API — `exit 1` с подсказкой, на PR — `::warning` без падения.

## 7. Распознавание скриншота

- **Подписи:** `dHash 17×16 (272 бит) + 4×4 средний цвет` — 820 байт/герой, 5 вариантов кадра (центр + сдвиги). Расстояние — Hamming + цветовая дельта, нормировано к 0–1.
- **Пороги:** `MATCH_MAX_SCORE 0.25`, `MIN_MARGIN 0.065`, `MAX_RATIO 0.73` — на 241 карточке с искажениями (blur/яркость/JPEG/55 % скейл) min margin 0.064 у верных vs 0.061 у посторонних — запас 0.004, ложных `ok` 0.
- **Сетка:** автопоиск по профилям яркости/градиента, подгонка фазы по узнаваемости, ручная правка `cols/rows ≤24`, `region` клампится по кадру (тест `300×108 → 300×98`).
- **Ограничения честно:** кадрирование ±11 % ширины — уже `weak`; баны обесцвечены, ряды с подписями — лучше резать по одному ряду вручную. Нужны реальные образцы карточек из игры для дополнительных кадров — отмечено в README.
- **Тест `test_recognize`:** синтетика из тех же иконок (ImageMagick), полосы, шум, масштабы, пустые слоты, обрезанные карточки, сдвинутая рамка, 2 строки, большая полоса — инвариант `ok ⇒ верный герой` держится.

**Рекомендация (Info):** собрать 5–10 реальных скриншотов пика (обрезанных клиентом) и добавить их как `data/templates-real.json` (опциональный overlay) — улучшит авто-режим без поломки синтетики.
